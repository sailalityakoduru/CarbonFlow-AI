# Project: Carbon-Aware AI Compute Orchestrator

Build a complete, responsive, professional web application named **Carbon-Aware AI Compute Orchestrator** for a hackathon project.

## 1. Project Objective

Develop an intelligent workload scheduling platform that reduces estimated carbon emissions from AI and computing workloads by selecting suitable execution times and computing regions.

The system must consider:
- Electricity carbon intensity and energy source mix.
- Estimated workload energy consumption.
- Job deadlines and priorities.
- CPU, GPU and memory requirements.
- Maximum acceptable waiting time and latency.
- Computing resource availability across regions.

The scheduler should automatically recommend whether to run a workload immediately, delay it until electricity is cleaner, or move it to another eligible region.

**Important:** Build a working application, not just a static UI. The scheduling logic, calculations, forms, charts and dashboard must work.

## 2. Technology Stack

Use the following technologies:
- Frontend: React with TypeScript.
- Build tool: Vite.
- Styling: Tailwind CSS.
- UI components: shadcn/ui where available.
- Icons: Lucide React.
- Charts: Recharts.
- Backend: Python with FastAPI, if a backend is supported by the Replit environment.
- Data processing and scheduling: Python, Pandas and NumPy where useful.
- Persistence: SQLite or a simple local JSON store if a backend is implemented.

If a Python backend would make the project significantly more complex, implement the entire MVP in React and TypeScript using localStorage. Choose one architecture and complete it rather than creating a partially working hybrid.

Do not use paid APIs, paid AI models or external cloud infrastructure.

### Page 3: Carbon Intelligence

Simulate three computing regions:
- Region A.
- Region B.

Each region should display:

- Renewable energy percentage.

Structure the application so a real carbon-intensity API can be integrated later, but do not require one now.

### Page 4: Smart Scheduler

Implement a real, explainable, carbon-aware scheduling algorithm.

Step 1: Calculate energy consumption.

Energy (kWh) = Average power (kW) × Runtime (hours).

Step 2: Estimate emissions.

Emissions (gCO₂e) = Energy (kWh) × Carbon intensity (gCO₂e/kWh).

Step 3: Generate candidate schedules.

Evaluate eligible hourly execution slots across the next 24 hours and the three simulated regions.

Step 4: Validate hard constraints.

Reject a candidate if:
- The workload would finish after its deadline.
- CPU, GPU or memory requirements cannot be met.
- The candidate exceeds the maximum waiting time.
- The region violates latency requirements.
- The workload is not allowed to move to another region.
- The workload is not allowed to wait.
- Any other mandatory workload constraint is violated.

Do not treat critical workloads as automatically delayable. Their urgency and deadline must be respected.

Step 5: Compare feasible options.

Estimate emissions for every feasible candidate. Select the candidate with the lowest estimated emissions. When emissions are similar, prefer shorter waiting time and lower cost.

Step 6: Generate a recommendation.

The result must be one of:
- RUN NOW.
- DELAY TO A CLEANER TIME.
- SHIFT TO ANOTHER REGION.
- NO FEASIBLE SCHEDULE.

For each recommendation, display:
- Selected execution time.
- Expected completion time.
- Selected region.
- Estimated energy consumption.
- Estimated carbon emissions.
- Deadline compliance.
- Expected waiting time.
- Reasons for the decision.

If no candidate is feasible, explain the specific constraint preventing scheduling. Never invent a feasible result.

For the initial prototype, schedule jobs independently using simulated resource availability. Clearly document that resource reservations and simultaneous multi-job capacity management are future extensions unless actually implemented.

### Page 5: Schedule Comparison

Compare two strategies using identical workloads and energy assumptions.

Baseline strategy:
Select the earliest feasible execution slot in the default region.

Carbon-aware strategy:
Select the feasible schedule with the lowest estimated emissions.

Show:
- Baseline emissions.
- Optimized emissions.
- Estimated grams of CO₂e avoided.
- Percentage emissions reduction.
- Energy consumption.
- Scheduling delay.
- Deadline compliance.
- Distribution of jobs across regions.

Use bar charts, metric cards and a schedule timeline.

Calculate carbon reduction using:

Carbon reduction (%) = ((Baseline emissions − Optimized emissions) / Baseline emissions) × 100

Handle a zero baseline safely and show the result as unavailable when the percentage cannot be calculated meaningfully.

Do not hardcode carbon savings or claim that the project has achieved a particular reduction without calculating it.
